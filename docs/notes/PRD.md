## 二、产品定义

### 2.1 产品目标

> **一句话**：为 Memos 增加一套独立、轻量的「长文笔记 + 知识库」能力，让用户既能随手记（现有 Memo），也能沉淀结构化、可链接、可共享的笔记（新增 Notes），并通过双链将两者打通。

**具体目标：**

1. **独立数据实体**：笔记不复用 Memo 表，拥有独立的数据表与 API，避免污染现有备忘录语义。
2. **类 Obsidian 编辑体验**：光标行显示 Markdown 源码、其余行渲染富文本的 Live Preview，支持基础 Markdown、代码高亮、双链 `[[...]]`、标签 `#tag`。
3. **双向链接打通 Memo 与 Note**：双链既能指向「笔记」也能指向「备忘录 Memo」，并支持反链查询。
4. **层级组织**：多层嵌套文件夹树，支持新建/重命名/删除文件夹与笔记、笔记跨文件夹移动。
5. **轻量协作**：私有（仅创建者可见）+ 文件夹级「共享工作区」（文件夹内所有笔记对全实例注册用户开放且完全控制权）。

### 2.2 目标用户与用户故事

| # | 用户故事 |
| --- | --- |
| US-1 | 作为 **Memos 个人用户**，我希望在侧边栏点开「笔记」进入独立笔记页，以便把长文、知识整理与日常随手记（Memo）分开管理。 |
| US-2 | 作为 **知识管理用户**，我希望在编辑器里用 `[[笔记标题]]` 和 `[[memo]]` 建立双向链接，以便在笔记与备忘之间跳转、查看反链，形成网状知识。 |
| US-3 | 作为 **内容创作者**，我希望粘贴/拖入图片后自动上传到资源库并内嵌显示，以便在笔记里配图而无需手动管理附件路径。 |
| US-4 | 作为 **团队/多用户实例成员**，我希望把某个文件夹标记为「共享工作区」，以便团队内所有注册用户对该文件夹下的笔记拥有完全读写删控制权。 |
| US-5 | 作为 **Obsidian 迁移用户**，我希望导入/导出 `.md` 文件（含图片资源），以便在 Memos 与 Obsidian 之间平滑迁移。 |

## 三、技术规范

### 3.1 需求池

> 优先级约定：**P0** 必须（MVP 阻断项）；**P1** 应该（MVP 完整度）；**P2** 可做（增强项）。

#### P0 —— 必须

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P0-1 | 侧边栏「笔记」入口 | 登录用户在 `Navigation` 侧边栏看到「笔记」入口，与「备忘录/发现/附件/通知」并列；点击进入笔记页；未登录用户不显示该入口。 |
| P0-2 | 独立数据实体 | 存在独立的 `notes` 数据表（SQLite/MySQL/PostgreSQL 三驱动迁移）与独立 API（proto 独立 service，如 `note_service` / `note_folder_service`）；**不复用** Memo 表。 |
| P0-3 | 笔记基础 CRUD | 支持新建/读取/更新/删除笔记；笔记含：标题、正文（Markdown 源码）、所属文件夹、创建者、创建/更新时间。 |
| P0-4 | Live Preview 编辑器 | 编辑器基于现有 TipTap + `@tiptap/markdown` codec；光标所在行显示 Markdown 源码，其余行渲染为富文本；保存后内容为 Markdown 文本。 |
| P0-5 | 基础 Markdown 渲染 | 支持标题(1-6)、列表（有序/无序/任务）、粗斜体、行内代码、代码块+高亮、引用、链接、图片、表格。 |
| P0-6 | 双链 `[[...]]` | 输入 `[[` 弹出候选（笔记 + Memo）；链接同时支持「笔记」与「备忘录 Memo」；点击可跳转。 |
| P0-7 | 标签 `#tag` 及反链 | 正文内 `#tag` 被识别为标签；可查看某标签的反链列表（引用该标签的笔记）。 |
| P0-8 | 文件夹树（多层嵌套） | 支持多层嵌套文件夹树；新建/重命名/删除文件夹；笔记可在文件夹间移动。 |
| P0-9 | 可见性-私有 | 笔记默认「私有」，仅创建者可见、可编辑。 |

#### P1 —— 应该

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P1-1 | 共享工作区（文件夹级） | 文件夹可被标记为「共享工作区」；该文件夹下所有笔记对全实例所有注册用户开放且拥有完全控制权（读写删）。共享状态在文件夹树上有明确标识。 |
| P1-2 | 搜索-标题模糊 | 支持按标题模糊搜索笔记；结果列表实时返回。 |
| P1-3 | 搜索-标签过滤 | 支持按标签过滤笔记列表。 |
| P1-4 | 搜索-双链反链查询 | 支持查询「引用了当前笔记/某链接目标」的反链列表。 |
| P1-5 | 图片上传 | 支持粘贴/拖入图片，上传到资源库（复用现有 Attachment 体系），并在正文内嵌显示。 |
| P1-6 | `.md` 导入 | 支持导入 `.md` 文件创建笔记（单文件即可，多文件批量导入为增强）。 |
| P1-7 | `.md` 导出 | 支持将笔记导出为 `.md` 文件（标题+正文 Markdown），可被 Obsidian 直接打开。 |

#### P2 —— 可做

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P2-1 | 批量 `.md` 导入 | 支持一次导入多个 `.md` 文件（含嵌套目录结构映射为文件夹）。 |
| P2-2 | 笔记全文搜索 | 除标题外，支持对正文全文检索。 |
| P2-3 | 笔记排序/置顶 | 支持按创建/更新时间排序、置顶常用笔记。 |
| P2-4 | 共享工作区权限细分 | 在「完全控制」之外，可选支持「只读」成员（后续扩展）。 |
| P2-5 | 快捷键 | 支持 `[[` 快速链接、`#` 快速打标签、Ctrl/Cmd+B/I 等编辑快捷键。 |

### 3.2 UI 设计稿

#### 3.2.1 侧边栏入口

```
┌─────────────────────────────┐
│  Memos  Logo                │
├─────────────────────────────┤
│  📚  备忘录  (Memos)         │
│  🌍  发现    (Explore)       │
│  📝  笔记    (Notes)  ← 新增  │
│  📎  附件    (Attachments)   │
│  🔔  通知    (Inbox)         │
├─────────────────────────────┤
│  👤  用户菜单                │
└─────────────────────────────┘
```
- 入口插在「发现」与「附件」之间（或紧随「备忘录」之后，最终位置由 UI 定稿确认），路由为 `/notes`。
- 使用现有 `NavLink` 组件 + `lucide-react` 图标（如 `FileTextIcon`/`NotebookIcon`），样式与其余入口一致。

#### 3.2.2 笔记列表页（含文件夹树）

```
┌──────────────────────────────────────────────────────────┐
│ 笔记                        [🔍 搜索]  [＋ 新建笔记]        │
├───────────────┬──────────────────────────────────────────┤
│ 文件夹树       │  笔记列表（当前文件夹/搜索结果）            │
│               │                                          │
│ ▾ 📁 我的笔记  │  ┌────────────────────────────────────┐  │
│   ▸ 📁 工作    │  │ 📝 产品需求 PRD        2 分钟前     │  │
│   ▾ 📁 学习    │  │ 📝 Go 学习笔记        昨天          │  │
│     📝 笔记A   │  │ 📝 读书摘录           3 天前        │  │
│ 📁 共享工作区🔗 │  └────────────────────────────────────┘  │
│   📝 会议纪要  │                                          │
└───────────────┴──────────────────────────────────────────┘
```
- 左侧为**多层嵌套文件夹树**：支持折叠/展开、右键菜单（新建文件夹/重命名/删除）、拖拽移动笔记。
- 「共享工作区」文件夹带 🔗 或不同底色标识（见 3.2.4）。
- 顶部搜索框支持「标题模糊 + 标签过滤」，结果区展示匹配笔记。

#### 3.2.3 编辑器布局（Live Preview）

```
┌──────────────────────────────────────────────────────────┐
│ ← 返回  笔记标题（可编辑）            [导出] [更多…]       │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  # 产品需求 PRD          ← 已渲染：一级标题               │
│                                                          │
│  ## 目标                ← 已渲染：二级标题               │
│  **这是一段加粗**        ← 已渲染：富文本                 │
│  [[备忘录]] [[Go笔记]]   ← 已渲染：双链（可点击）          │
│  #产品 #笔记            ← 已渲染：标签                     │
│  **当前行：## 目标**     ← 光标所在行：显示 Markdown 源码   │
│                                                          │
│  ```go                  ← 代码块，带语法高亮               │
│  func main() {}                                           │
│  ```                                                      │
│                                                          │
└──────────────────────────────────────────────────────────┘
```
- **Live Preview**：光标所在行显示 Markdown 源码，其余行渲染为富文本；点击富文本任意行即切到源码编辑。
- 复用现有 TipTap 编辑器扩展（StarterKit、Heading、TaskList、Markdown codec、Tag），新增双链 `[[...]]` 扩展与图片内嵌。
- 图片：粘贴/拖入 → 调用资源上传接口 → 返回 URL → 插入 `![](url)` 并内嵌显示。

#### 3.2.4 共享工作区标识

```
文件夹树：                         编辑页顶部：
  📁 共享工作区  🔗  (共享标识)        [🔗 共享工作区 · 全员可编辑] 徽标
  └── 📝 会议纪要                    （非创建者打开时显示「可读写」）
```
- 标记为共享的文件夹在树中显示 `🔗`/高亮底色；进入其笔记后，编辑器顶部显示共享徽标。
- 私有笔记无任何共享标识。

### 3.3 数据/API 概述（供架构师参考）

- 新增实体：`note`（笔记）、`note_folder`（文件夹，含 `parent_id` 支持多层级 + `shared` 共享标记）。
- 双链解析：正文中 `[[目标]]` 运行时解析到 `note` 或 `memo`；反链通过查询正文内容建立（建议存储时抽取 link/tag 关系，具体实现由架构师定）。
- 复用：图片上传复用现有 `attachment`（原 Resource）体系。

### 3.4 非功能要求

- 三驱动（SQLite/MySQL/PostgreSQL）迁移一致，遵循 `store/migration/{sqlite,mysql,postgres}/`。
- 笔记正文大小应支持长文（≥ 1MB Markdown 文本不崩溃/不截断）。
- 权限校验在服务端强制，前端仅做体验层控制。

## 四、待确认问题

1. **术语差异**：需求用「资源 Resource 附件体系」，但当前代码已重命名为 `attachment`（`attachment_service.proto`）。确认统一按现有「Attachment」实现，PRD 已按此表述。
2. **入口位置**：侧边栏「笔记」放在「备忘录」之后，还是「发现/附件」之间？是否有图标偏好？
3. **双链到 Memo 的呈现**：`[[memo]]` 是链接到某个具体 Memo（按标题/UID 解析），还是仅作为文本标签？点击跳转目标与权限（私有 Memo 他人不可见）如何处理？
4. **共享工作区边界**：共享的粒度是「文件夹」还是「笔记」？子文件夹是否继承父文件夹的共享状态？删除共享文件夹时是否需二次确认并级联处理子项？
5. **反链存储**：双链/标签关系是「写入时解析入库」还是「读取时实时扫描正文」？影响搜索性能与实现复杂度。
6. **导入冲突**：`.md` 导入时若标题与已有笔记重名，覆盖、跳过还是自动重命名？
7. **Live Preview 实现范围**：光标「行级」源码 vs 光标「块级」源码（Obsidian 为块级）？是否首版只需行级即可。
8. **并发/自动保存**：编辑器是否需要自动保存（类似现有 Memo 的 autosave），还是手动保存？多用户同时编辑共享笔记是否需冲突处理（首版可先不做）。
9. **笔记可见性枚举**：是否需要第三态（如「PROTECTED 仅共享链接可见」），还是严格只有「私有 / 共享工作区」两种？
